# Codeforces Round 460 (Div. 2) D. [Substring](https://codeforces.com/contest/919/problem/D)

This is a classic problem that can be solved with **topological sort + dynamic programming**.

## Analysis

If you view DP as a graph, where every DP state is a node and every transition is an edge, the states of a deterministic DP form a **DAG** (directed acyclic graph). We can never return to a previous state, so the process only moves forward. This is exactly why DP works on DAGs.

**Why must a valid graph have no cycle?** The problem says: *"If the value can be arbitrarily large, output -1 instead."* When can that happen? Only when the graph contains a cycle. If you wanted the largest possible path value and found a cycle, you would loop around it over and over, and the value would grow without bound. So a valid answer requires a graph with no cycle.

This gives us a plan. DP computes the answer on a DAG, and **Kahn's algorithm** (a topological sort) lets us detect cycles at the same time. So we use **DP + Kahn**.

## Defining the DP state

The problem defines a path's value as the count of its most frequent letter. For example, the path `abaca` has value 3. We need the path with the largest value.

Define `dp[i][j]` (with `i ∈ [1, n]`, `j ∈ [0, 25]`) as the **maximum number of occurrences of letter `j` over all paths ending at node `i`**.

We run Kahn's algorithm on the graph. When node `v` is popped from the queue:

1. Count its own letter: `dp[v][s[v] - 'a']++`.
2. For every node `u` reachable from `v`, update `dp[u][c] = max(dp[u][c], dp[v][c])` for all 26 letters `c`.

## Code

**Initial setup.** I use global variables to keep the code short.

```cpp
#include <bits/stdc++.h>
using namespace std;
#define ll long long

void setIO(const string& name = "") {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    if (!name.empty()) {
        freopen((name + ".in").c_str(), "r", stdin);
        freopen((name + ".out").c_str(), "w", stdout);
    }
}

vector<vector<ll>> graph;   // adjacency list
vector<ll> indegrees;       // indegree of each node
vector<vector<ll>> dp;      // dp[i][c]: best count of letter c on a path ending at i
string s;                   // letter of each node
```

**Input.**

```cpp
int main() {
    setIO();
    ll n, m;
    cin >> n >> m;
    cin >> s;
    graph.resize(n + 1);
    indegrees.resize(n + 1);
    dp.assign(n + 1, vector<ll>(26, 0));
    for (ll i = 0; i < m; ++i) {
        ll u, v;
        cin >> u >> v;
        graph[u].push_back(v);
        indegrees[v]++;
    }
    kahn();
    return 0;
}
```

**Kahn's algorithm with DP.**

```cpp
void kahn() {
    queue<size_t> q;
    ll cnt = 0;  // number of nodes processed
    for (size_t i = 1; i < indegrees.size(); ++i) {
        if (indegrees[i] == 0) q.push(i);
    }
    while (!q.empty()) {
        cnt++;
        size_t v = q.front();
        q.pop();
        dp[v][s[v - 1] - 'a']++;
        for (ll u : graph[v]) {
            indegrees[u]--;
            if (indegrees[u] == 0) q.push(u);
            for (size_t c = 0; c < 26; c++) {
                dp[u][c] = max(dp[u][c], dp[v][c]);
            }
        }
    }

    if (cnt < (ll)indegrees.size() - 1) {
        cout << -1;
    } else {
        ll ans = 0;
        for (size_t i = 1; i < indegrees.size(); ++i)
            for (size_t j = 0; j < 26; ++j)
                ans = max(ans, dp[i][j]);
        cout << ans;
    }
}
```

## Code explanation: `kahn()`

**1. Initialization.** We push every node with indegree 0 into the queue. These are the start points of the topological order. `cnt` records how many nodes we process.

**2. Processing a node.** When we pop node `v`, all of its predecessors have already been processed, so `dp[v]` is final except for `v`'s own letter. We add it with `dp[v][s[v-1] - 'a']++`. (`s` is 0-indexed while nodes are 1-indexed, hence `v-1`.)

**3. Relaxing edges.** For each edge `v → u`:
- `indegrees[u]--` removes the edge `v → u` from the graph. When `u`'s indegree reaches 0, all its predecessors are done, so `u` joins the queue.
- `dp[u][c] = max(dp[u][c], dp[v][c])` for every letter `c` carries the best counts along the edge. Since `u` may have several predecessors, we take the maximum over all of them. `u` then adds its own letter when it is popped.

**4. Cycle detection.** Nodes on a cycle (or reachable only through one) never reach indegree 0, so they never enter the queue. If `cnt < n`, some nodes were never processed, so the graph has a cycle and we print `-1`. A self-loop counts as a cycle too.

**5. Answer.** If every node was processed, the graph is a DAG. The answer is the largest `dp[i][j]` over all nodes and letters, meaning the best count of any single letter on any path.

**Complexity.** Each node is processed once and each edge once, with a 26-letter update per edge, so the time is **O(26·(n + m))** and the memory is **O(26·n + m)**.
