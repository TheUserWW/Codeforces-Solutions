# [CodeForces 1195 C. Basketball Exercise](https://codeforces.com/contest/1195/problem/C)

This is a very typical dynamic programming problem. In this reading, I will show you three ways to solve this problem using dynamic programming.

## Problem Analysis

First, we have to analyze the problem. According to the context, we know that there are four restrictions we have to follow when we choose students:

1. Choose players from left to right.
2. The index of each chosen player (excluding the first one taken) must be strictly greater than the index of the previous player.
3. Demid chooses students in such a way that no consecutive chosen students belong to the same row.
4. The total height of all chosen students is maximum possible.

According to these conditions, we can try to define states for dynamic programming.

When we design a state, we have to make sure that each state fulfills two fundamental features:

1. Each state can clearly reflect the restriction given above.
2. Each state is independent of the future.

The second condition is particularly important, since the key point of dynamic programming is that we deduce the optimal result from the optimal previous case. In other words, we have to make sure that the state contains enough information to determine the future without relying on any unprocessed history.

## First Solution

So, let's make things easy. Since we can only choose people from left to right, one intuitive way to define a state is to define `dp[i]`, which means the optimal combination when we are choosing people up to index `i`.

However, we also need to know which row the last chosen student came from. Therefore, a better state is `dp[i][j]`.

We can define `dp[i][j]` so that it clearly describes what exactly happened at `i`.

Specifically, I defined `dp[i][j]` as: when we are going to index `i`, what is the optimal result if we choose to implement operation `j`.

This sounds a little abstract, but it is actually quite clear. `j` is an integer in the interval `[0, 2]`:

- `j = 0` means we pick a player from row A.
- `j = 1` means we pick a player from row B.
- `j = 2` means we skip picking a player at `i`.

Again, the meaning of `dp[i][j]` is the optimal combination (maximum possible total height of players) we can get when we reach the `i`th index and perform operation `j`.

At the end, the result would be `max(dp[n][0], dp[n][1], dp[n][2])`.

## State Transition

After we define the state, let us figure out how to write the state transition equation.

This step is particularly easy after you define an appropriate state. The only thing we have to do (at least in this problem) is simulate.

One of my favorite ways to get the state transition equation is to write some base cases first.

So, let us write the case when `i = 0`.

The answer is very clear: if `i = 0`, it means we have not chosen anyone yet, so no matter what you did, all `dp[0][j] = 0`.

How about `i = 1`?

It means we are deciding how to make an operation for the first person.

If we choose to pick a person from row A, we get the first person from row A. So currently, the total maximum height of a team is equal to `rowA[0]` (since I use 0-based indexing), so `dp[1][0] = rowA[0]`.

Similarly, if we choose to pick a person from row B, the total maximum height of a team is equal to `rowB[0]`, so `dp[1][1] = rowB[0]`.

What if we give up on choosing a person at index `0`? The answer is easy: the total maximum height in that case is `0`. So, `dp[1][2] = 0`.

## General Case

Now, we get some base cases. What if we want to know the general case `i`?

Let us make some deduction.

For `dp[i][0]`: if we pick a person from row A at `i`, what is the best result?

First, we know the equation must look like this: `a[i] + max(something)`.

You may be confused about how to understand `a[i] + max(something)`. You can think of it this way: now we are at position `i`, and we are going to choose an operation such that we want to pick a player from `rowA[i]`. `rowA[i]` means a player in row A at position `i`. `something` is a set of possible previous states. `max()` means to choose the best one. Now, I will tell you how to figure out these situations.

Back to the rules above, we know that "no consecutive chosen students belong to the same row." Thus, our previous step choice is absolutely not to choose a player from row A. However, the previous state could be `dp[i-1][1]`, `dp[i-1][2]`, or even `dp[i-2][0]`.

Could our previous operation be `dp[i-1][1]` or `dp[i-1][2]`? Absolutely yes. We can definitely choose to pick up a person from row B or just do nothing in the previous step.

So, the state transition is:

$$dp[i][0] = \max(dp[i-1][1], dp[i-2][0], dp[i-1][2]) + rowA[i-1]$$

Same logic for `dp[i][1]`:

$$dp[i][1] = \max(dp[i-2][1], dp[i-1][0], dp[i-1][2]) + rowB[i-1]$$

There is no restriction for skipping a player, so:

$$dp[i][2] = \max(dp[i-1][0], dp[i-1][1], dp[i-1][2])$$

The reason I use `rowA[i-1]` or `rowB[i-1]` with index `i - 1` is that I set my DP array as 1-based indexing, but `rowA` and `rowB` are 0-based indexing.

Here is the proving:
Why dp[i][2] Can Be Removed (Algebraic Proof)

To keep the notation short, write

A_i = dp[i][0]
B_i = dp[i][1]
C_i = dp[i][2]

Our original transitions, for i ≥ 2, are:

$$A_i = \max(B_{i-1},\ A_{i-2},\ C_{i-1}) + rowA[i-1]$$
$$B_i = \max(A_{i-1},\ B_{i-2},\ C_{i-1}) + rowB[i-1]$$
$$C_i = \max(A_{i-1},\ B_{i-1},\ C_{i-1})$$

Claim. For i ≥ 2, the transitions can be rewritten as:

$$A_i = \max(A_{i-2},\ B_{i-1},\ B_{i-2}) + rowA[i-1]$$
$$B_i = \max(B_{i-2},\ A_{i-1},\ A_{i-2}) + rowB[i-1]$$

Since C no longer appears, we can drop it entirely.

Step 1: Expand C_{i-1}

The equation for C holds for every index k ≥ 1. For k = 1 it still holds because C_1 = 0 = max(A_0, B_0, C_0). Applying it with k = i-1 gives:

$$C_{i-1} = \max(A_{i-2},\ B_{i-2},\ C_{i-2})$$
Step 2: Substitute into A_i

Let M be the part inside the max of A_i:

$$M = \max(B_{i-1},\ A_{i-2},\ C_{i-1})$$

Replacing C_{i-1} with the expansion from Step 1:

$$M = \max(B_{i-1},\ A_{i-2},\ \max(A_{i-2},\ B_{i-2},\ C_{i-2}))$$

Because max(x, x) = x, the duplicated A_{i-2} collapses, so:

$$M = \max(B_{i-1},\ A_{i-2},\ B_{i-2},\ C_{i-2})$$

Compared with the claim, the only extra term is C_{i-2}. We now show it never matters.

Step 3: Lemma, C_{k-1} ≤ B_k and C_{k-1} ≤ A_k for all k ≥ 1
Base case k = 1: C_0 = 0, while B_1 = rowB[0] ≥ 0 and A_1 = rowA[0] ≥ 0. ✔
Case k ≥ 2: From the transition for B_k,
$$B_k = \max(A_{k-1},\ B_{k-2},\ C_{k-1}) + rowB[k-1] \ \ge\ C_{k-1} + rowB[k-1] \ \ge\ C_{k-1}$$

The last step holds because heights are positive (rowB[k-1] ≥ 1). The same argument gives A_k ≥ C_{k-1}. ∎

Intuitively, skipping index k-1 can never beat picking someone at index k right after the same prefix, because picking only adds a positive height.

Step 4: Remove C_{i-2}

Apply the lemma with k = i-1. Since i ≥ 2, we have k ≥ 1, so:

$$C_{i-2} \le B_{i-1}$$

So C_{i-2} is never larger than B_{i-1}, which is already inside the max. Dropping it does not change the maximum:

$$M = \max(B_{i-1},\ A_{i-2},\ B_{i-2})$$

Therefore:

$$\boxed{A_i = \max(A_{i-2},\ B_{i-1},\ B_{i-2}) + rowA[i-1]}$$
Step 5: The symmetric case for B_i

The same argument with the roles of A and B swapped works. Using Step 1 again and the lemma C_{i-2} ≤ A_{i-1}:

$$\max(A_{i-1},\ B_{i-2},\ C_{i-1}) = \max(A_{i-1},\ B_{i-2},\ A_{i-2},\ C_{i-2}) = \max(A_{i-1},\ B_{i-2},\ A_{i-2})$$
$$\boxed{B_i = \max(B_{i-2},\ A_{i-1},\ A_{i-2}) + rowB[i-1]}$$
Final answer without C

The answer was max(A_n, B_n, C_n). Since C_n = max(A_{n-1}, B_{n-1}, C_{n-1}) and C_{n-1} ≤ A_n by the lemma, we get:

$$\text{answer} = \max(A_n,\ B_n,\ A_{n-1},\ B_{n-1})$$

With n ≥ 1 and A_0 = B_0 = 0, this is simply max(A_n, B_n, A_{n-1}, B_{n-1}).
So, our code can be written as
