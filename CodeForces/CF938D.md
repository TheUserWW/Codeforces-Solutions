[CodeForces - 938D](https://codeforces.com/contest/938/problem/D)

This is a shortest path problem. In this problem, we need to find the minimum number of coins a person starting from city `i` must spend to travel to some city `j`.

One of the most useful algorithms for this is Dijkstra's algorithm, but we need to make a small modification to the original version.

As the statement says, `j` is not a fixed vertex. That means we only need to find a path starting from `i` and ending at any city `j` (where `j` may equal `i`) such that the total cost is minimized.

This is exactly why Dijkstra's algorithm is so useful: once we run it from a starting point `i`, we automatically get the shortest path from `i` to every other point. This is a crucial feature because it lets us avoid running Dijkstra's algorithm for every given vertex separately.

Of course, we could actually do that, but it would be too slow.

2. Write the core part

This is the most important step. Let us figure out how to implement Dijkstra specifically for this problem.

We know that the time complexity of Dijkstra is roughly `O((n + m) log n)`. If we implement Dijkstra for every single element, the time complexity becomes `O(m * n log n)`, which is extremely inefficient.

So how can we avoid this?

The easiest way is to run Dijkstra only once, but process all vertices simultaneously.

In that case, the time complexity goes back to `O((n + m) log n)`.

I believe this might be confusing at first, so let me explain.

First, we need to write the function header:

```cpp
void dijkstra(auto& graph, auto& price) {}
```

At this moment, I need to point out one important difference from the classic shortest path problem: according to the problem statement, we have to buy a ticket at city `i`. This means that each city `i` has a weight. Therefore, even at the starting point, the cost is not zero. Instead, we have to initialize:

`dist[i] = price[i]`

which means that if we start at point `i`, the total cost is initially the price of that city.

```cpp
size_t n = graph.size() - 1;
vector<ll> dist(n + 1, LLONG_MAX);
priority_queue<pair<ll, ll>, vector<pair<ll, ll>>, greater<>> pq;

for (int i = 1; i <= n; i++) {
    dist[i] = price[i];
    pq.emplace(dist[i], i);
}
```

Then, we can simply run Dijkstra in the usual way:

```cpp
while (!pq.empty()) {
    auto [w, v] = pq.top();
    pq.pop();

    if (w != dist[v]) {
        continue;
    }

    for (auto [u, d] : graph[v]) {
        if (dist[u] > dist[v] + 2LL * d) {
            dist[u] = dist[v] + 2LL * d;
            pq.emplace(dist[u], u);
        }
    }
}

for (int i = 1; i <= n; i++) {
    cout << dist[i] << " ";
}
```

Why does this work? The reason is actually quite simple:

First, we insert all vertices into the priority queue at the initial stage, which is valid for Dijkstra's algorithm. Second, this method is more efficient because the algorithm can reuse computations across multiple vertices.

If we run Dijkstra separately for every vertex, many edges are processed repeatedly. In this problem, however, a short segment of code allows us to share those computations surprisingly well:

```cpp
if (w != dist[v]) {
    continue;
}
```

This ensures that stale entries are ignored. For example, after processing vertex `a2` after `a1`, the program may still have a chance to reuse many common edges.

Therefore, it will be faster.
