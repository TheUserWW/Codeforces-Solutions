# Codeforces 938D - Buy a Ticket

[Codeforces - 938D](https://codeforces.com/contest/938/problem/D)

## Problem Idea

This is a shortest path problem. We need to find the minimum number of coins a person starting from city `i` must spend to travel to some city `j`.

A natural idea is to use Dijkstra's algorithm, but with one important modification: the destination city `j` is not fixed. We only need the minimum cost to reach any city from `i`, where `j` may even be equal to `i`.

This is exactly why Dijkstra is useful: if we run the algorithm from a starting city `i`, it gives us the shortest distance from `i` to every other city.

---

## Key Observation

The real challenge is not the shortest path itself, but the cost of the ticket we must pay when entering a city.

For this problem, the cost to move from city `u` to `v` via an edge of weight `d` is:

- `2 * d` because we must pay for the trip there and back in the transformed model
- plus the ticket cost of the destination city if the journey ends there

The key to reducing the complexity is to avoid running Dijkstra from every city individually.

Instead, we initialize every city as a source with its ticket price, and run a single multi-source Dijkstra.

---

## Why Not Run Dijkstra for Every City?

A straightforward solution would be:

- run Dijkstra from each city `i`
- compute the minimum cost from `i` to all others

This is too slow, with complexity roughly:

- `O(n * (n + m) log n)`

which is far too large for the constraints.

Instead, we can do this in one pass:

- initialize `dist[i] = price[i]`
- push all vertices into the priority queue initially
- run Dijkstra once on the whole graph

This reduces the total complexity to:

- `O((n + m) log n)`

One important detail: the variables `u`, `v`, and `w` must be of type `long long`. Using `int` may overflow, especially when the graph weights are large.

## Core Idea: Multi-Source Dijkstra

We start by thinking of each city as a possible starting point with its own initial cost.

So the initialization is:

```cpp
size_t n = graph.size() - 1;
vector<ll> dist(n + 1, LLONG_MAX);
priority_queue<pair<ll, ll>, vector<pair<ll, ll>>, greater<>> pq;

for (int i = 1; i <= n; i++) {
    dist[i] = price[i];
    pq.emplace(dist[i], i);
}
```

Then we run the standard Dijkstra process:

```cpp
while (!pq.empty()) {
    auto [w, v] = pq.top();
    pq.pop();

    if (w != dist[v]) {
        continue;
    }

    for (auto [u, d] : graph[v]) {
        if (dist[u] > dist[v] + 2LL * d) {
            dist[u] = dist[v] + 2LL * d;
            pq.emplace(dist[u], u);
        }
    }
}

for (int i = 1; i <= n; i++) {
    cout << dist[i] << " ";
}
```

---

## Why This Works

The reason is simple and elegant.

- Each city `i` is inserted into the priority queue with its initial cost `price[i]`.
- This means that every city is treated as a valid starting point in the same Dijkstra run.
- Dijkstra then propagates the minimum possible cost through the graph.
- Because we use a priority queue and ignore stale entries with:

```cpp
if (w != dist[v]) continue;
```

we avoid redundant updates and keep the algorithm efficient.

This method reuses computations across many sources, which is exactly why it is much faster than running Dijkstra separately from every city.

---

## Final Summary

The key idea is:

- initialize each city with its ticket price,
- run a single multi-source Dijkstra,
- and use the shortest distances to answer the problem.

This technique is both efficient and correct for the given constraints.

---

## Complexity

- Build graph: `O(m)`
- Multi-source Dijkstra: `O((n + m) log n)`
- Total: `O((n + m) log n)`

This is fast enough for the problem limits.
